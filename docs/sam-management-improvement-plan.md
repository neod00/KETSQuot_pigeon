# 전략고객 관리(SAM) 운영·화면 개선안

작성일: 2026-11-04 · 대상: https://lrqa-korea-portal.netlify.app/iso/sam

최신 사용자 조건: Outlook에 이미 5개 Account 폴더가 있으며 관련 메일을 각 폴더에 모은다. 회사 환경에서 Graph와 전용주소 전달을 사용할 수 없으므로 **Account 선택 → .eml/.msg 파일 여러 개 드래그 또는 파일 선택 → 미리보기 → AI 정리 → 결과 검토**를 현재 구현 방식으로 채택했다. 아래의 Graph·전용주소·자동수집 제안은 현재 적용 대상에서 제외한다. 직접 Outlook에서 브라우저로 드래그가 지원되지 않는 환경은 PC에 저장한 메일 파일을 올린다. 업로드는 30개·파일당 10MB까지이며, 첨부파일 내용은 분석하지 않는다. 자동 승인·업무 생성은 후속 범위이며 현재 결과는 기존 AI 초안 검토 흐름에 연결된다.

**추천 방향: Outlook 업무 메일을 기본 입력으로 삼고, 고객별 전략과 진행 이력을 ‘이번 주 실행할 업무·의사결정’에 연결한다.** 사용자는 평소처럼 메일로 업무를 진행하며 SAM은 관련 메일을 모아 고객 현황과 후속 업무를 정리한다. 메모는 통화·대면회의처럼 메일에 없는 내용의 보완 수단으로 둔다. 계열사별 영업기회 연결, AI 정리, 회의 모드, 영문 검토, Excel·PPTX 출력은 기존 기능을 활용한다.

검토 범위는 연결된 프로젝트의 화면·API·데이터 모델·출력 코드다. 로그인한 운영 화면과 실제 고객 데이터는 확인하지 않았으므로 고객별 현황, 누락 건수, 현재 실적에 대한 판단은 포함하지 않는다. 아래 수치와 일정은 운영 제안이며 현재 측정값이나 개발 기간 확약이 아니다.

## 우선 반영: Outlook 메일 중심 운영

사용자의 실제 업무는 대부분 Outlook에서 이루어진다. 따라서 메일을 다시 메모로 옮기는 작업을 없애는 것을 최우선으로 한다.

```text
Outlook 관련 수신·발신 메일
  → SAM 대상 폴더 또는 전달용 수신함
  → Account·계열사·영업기회 연결
  → 대화별 변경사항·요청·약속·다음 업무 추출
  → 고객 활동 이력과 이번 주 업무에 표시
  → 분류 불명확·중요 변경만 확인함으로
```

**현재 구현:** `.eml` 업로드와 Outlook Web의 `SAM-AI 대상` 폴더를 읽는 로컬 Edge 수집기가 있다. 수집기는 고객명·계열사·별칭을 이용해 Account를 선택하고 한·영 진행현황 초안을 만든다. 현재는 초안 승인 후 이력에 반영된다. 메일 본문은 AI 분석 요청에 사용하고 앱에는 초안·메일 참조정보를 저장하는 구조다. 실제 수집기 설정·작업 스케줄 등록·운영 가동 여부는 이번 검토에서 확인하지 않았다.

**사용 방식 제안:** 먼저 기존 대상 폴더를 활용한다. 관련 발신자·수신자·계열사 도메인 등의 규칙으로 대상 메일을 모으고, 예외 메일만 사용자가 지정한다. 전용 주소로 전달하는 방식도 만들 수 있으나 현재 SAM 전용 수신주소는 구현에서 확인되지 않았다. 해당 방식은 수신함과 연결 처리를 새로 구성해야 한다.

**사용자가 매번 승인하지 않도록 하는 기준:** 근거 메일이 명확한 요약과 활동 이력은 ‘자동 정리’ 표시 및 원문 참조와 함께 누적한다. 업무는 ‘요청받음 / 내가 약속함 / 상대방 회신 대기’로 나누고, 명시된 담당자·기한을 추출한다. 고객이나 담당자 연결이 애매한 항목, 기존 기한과 충돌하는 변경, 수주 확정·금액·위험 해소 등 중요한 변경만 확인 대상으로 남긴다. 새로운 약속이나 날짜를 AI가 만들어 확정하지 않는다. 자동 생성한 항목은 수정·제외할 수 있고 처리 근거를 확인할 수 있어야 한다.

**수집 정확도 보완:** 받은 메일뿐 아니라 사용자가 보낸 답장도 연결한다. 수신만 확인하면 이미 회신한 업무를 계속 대기로 표시할 수 있다. 메일별 식별자와 대화 관계를 함께 사용하여 새 답장은 반영하고 인용된 과거 본문은 중복 업무로 만들지 않는다. 기존 수집기의 최근 표시 대화 중심 처리와 건너뛰는 미분류 메일은 각각 증분 수집·미분류함으로 보완한다. ‘회신 없음’은 해당 수신·발신 범위가 정상 수집된 경우에만 판정한다.

**연결 경로:** 기존 PC 수집기로 시범 운영을 시작할 수 있다. 상시 운영은 Microsoft Graph의 폴더별 변경분 조회를 활용하는 방향을 권한다. Power Automate의 특정 폴더 신규 메일 트리거도 후보이며, 신규 수신·수동 이동·보낸 메일·과거 메일의 수집 동작을 각각 검증해야 한다. 조직에서 허용하는 연결 방식과 권한에 맞춰 선택하며 이번 제안에서 계정 연결이나 메일 전송을 실행하지 않았다. [Microsoft Graph 변경분 조회](https://learn.microsoft.com/en-us/graph/delta-query-messages), [Power Automate 메일 트리거](https://learn.microsoft.com/en-us/power-automate/email-triggers).

메일 우선 1차 완료 기준은 **관련 수신·발신 수집 → Account 연결 → 중복 없는 요약·업무 생성 → 예외 확인함 → 처리 상태·마지막 수집 시각 표시**다. 같은 메일 재수집 시 중복되지 않고, 같은 대화의 새 답장은 누락되지 않으며, 분류 실패 메일을 사용자가 찾을 수 있어야 한다. 첨부파일 내용 분석은 별도 지원 범위로 표시하고 본문에 없는 계약금액·조건을 추정하지 않는다.

## 1. 현재 기능에서 연결이 끊기는 지점

| 현재 확인된 상태 | 업무 영향 | 개선 방향 |
|---|---|---|
| 메모의 ‘다음 조치’는 서술형이며 진행현황 하나에 담당자·기한 한 쌍이 붙는다. 별도 Action 데이터 구조는 있지만 상세 편집 흐름이 부족하다. | 여러 후속조치의 개별 완료·지연·재배정을 추적하기 어렵다. | 메모에서 실행과제를 분리하고 담당자·기한·완료 상태를 각각 관리한다. |
| 대시보드는 고객 목록과 요약 지표 중심이다. | 매번 고객을 열어 우선 처리할 일을 찾아야 한다. | 기한 초과·검토 도래·지원 요청·미승인 초안을 첫 화면에 모은다. |
| 고객별 매주·격주·월간 검토 설정이 있으나 회의 화면의 오래된 업데이트 경고는 30일 고정이다. | 주간 검토 고객의 지연을 늦게 발견할 수 있다. | 내부 검토 예정일과 실제 검토 완료일을 기준으로 판정한다. |
| 목록은 계정 위험값, 회의 화면은 최신 진행현황 상태를 우선 사용한다. | 같은 고객이 화면마다 다른 상태로 보일 수 있다. | 위험 상태의 출처를 통일하고 업무 지연과 고객 위험을 구분한다. |
| 대시보드는 활성 Pipeline, 회의 화면은 연결된 전체 영업건을 합산한다. | 동일하게 보이는 금액을 서로 다른 범위로 비교할 수 있다. | 활성·보류·수주·실주를 구분하고 합계의 범위와 기준일을 표시한다. |
| ‘승인 영문만 출력’이라는 안내와 달리 출력 코드가 영문 승인 상태를 검사하지 않는다. | 미승인 문구가 정식 보고서에 포함될 수 있다. | 정식 출력 전 승인·누락 검사를 적용하고 초안 출력은 별도로 표시한다. |

## 2. 추천 화면 구조

상위 탭을 **이번 주 관리 / 전략고객 / 검토회의 / 보고·출력**으로 정리한다. 기존 영문 검토와 출력·문서는 ‘보고·출력’ 안에서 이어지도록 한다. 고객 상세는 ‘요약 / 실행과제 / 영업기회·계열사 / 관계자 / 활동 이력 / 보고정보’로 구분하고, 기존 영문 필드 편집은 보고정보에 모은다.

다음은 구조 예시이며 실제 고객·건수는 아니다.

```text
전략고객 관리 SAM
[이번 주 관리]  [전략고객]  [검토회의]  [보고·출력]

담당자: 내 업무 / 전체 / 선택    기간: 이번 주    고객 검색

[기한 초과] [7일 내 마감] [검토 예정] [지원 요청] [승인 대기]

우선 처리할 업무
구분       고객·관련 기회     할 일               담당자    기한      처리
기한 초과  예시 고객 A       제안 범위 회신 확인   담당 A    11/03    [업무 열기]
결정 필요  예시 고객 B       기술인력 배정 결정    책임 B    11/05    [결정 기록]
검토 예정  예시 고객 C       월간 검토             담당 C    11/06    [검토 시작]

고객 선택 → 고객 요약
관리책임자 · 내부 후원자 · 고객 의사결정자
90일 목표 / 주요 기회 / 최근 접촉 / 다음 접촉 / 위험 및 대응
[진행현황 입력] [업무 추가] [회의 안건 등록]
```

목록은 기한 초과 → 관리자 결정 필요 → 기한 임박 순으로 정렬한다. ‘마감까지 남은 날짜’와 ‘우선순위가 높은 이유’를 표시한다. 업무 미등록·담당자 없음·기한 없음은 별도 보완 항목으로 보여주며 정상으로 간주하지 않는다. 완료·배정·기한 변경은 목록 또는 옆 패널에서 처리하고 변경 이력을 남긴다.

## 3. 입력 한 번으로 실행과 보고까지 이어지는 흐름

1. Outlook 대상 메일을 수집한다. 통화·대면회의에서만 확인된 내용은 짧은 메모로 보완한다.
2. AI가 고객·대화별 요약·위험·지원 요청·다음 업무를 추출한다. 본문에 명확한 사실과 확인이 필요한 후보를 구분한다.
3. 명확한 활동은 자동 누적하고 예외 항목만 사용자가 확인한다. 기존 업무와 연결할 수도 있다. 동일한 원본 재수집·재승인으로 업무가 중복 생성되지 않아야 한다.
4. 등록된 업무가 담당자의 ‘이번 주 관리’와 고객 상세에 동시에 나타난다. 업무별로 진행·완료·보류·취소를 관리한다.
5. 주간 회의에서는 위험·지연·지원 요청과 지난 회의 이후 변화를 검토한다. 결정마다 담당자와 기한을 확정한다.
6. ‘검토 완료’ 시 다음 검토일을 주기에 따라 제안하고 사용자가 확정한다. 단순 메모 등록은 검토 완료로 처리하지 않는다.
7. 보고 시 변경된 내용의 영문을 검토하고 승인된 버전을 출력한다. 정식 출력에 필요한 미승인·누락 항목을 먼저 안내한다.

기존 진행현황은 이력으로 유지하고 실행과제와 연결한다. 원본 메모 수정·추가가 이미 완료된 업무를 다시 열거나 기존 기한을 조용히 덮어쓰지 않도록 한다. 관리자 지원 요청도 요청자·결정 책임자·요청 기한·결정 결과를 가진 항목으로 관리한다.

## 4. 고객별 전략관리 항목

| 관리 영역 | 최소 관리 항목 | 관리 방식 |
|---|---|---|
| 고객 목표 | 90일 목표 1~3개, 성공 기준, 책임자 | 고객 유지·신규 진입·서비스 확대 등 구체적 결과를 쓰고 관련 기회·업무와 연결한다. |
| 영업기회 | 원본 영업 ID, 거래 계열사, 서비스, 단계, 금액·통화, 마감 예정일, 담당자 | 기존 세일즈·D365 데이터를 기준으로 조회한다. SAM에 같은 단계·금액을 반복 입력하지 않는다. |
| 핵심 관계자 | 소속 계열사, 역할, 영향력, 관계 상태, 내부 관계 책임자, 최근·다음 접촉 | 기존 Contact 구조에 편집 화면과 접촉 이력을 연결한다. 미접촉 의사결정자를 확인할 수 있게 한다. |
| 실행과제 | 제목, 고객, 선택적 기회 ID, 담당자, 기한, 상태, 완료일, 원본 이력 ID | 기존 Action 구조를 확장한다. ‘기한 초과’는 미완료 상태와 기한에서 계산한다. |
| 내부 검토 | 주기, 지난 완료일, 다음 예정일, 결정사항 | 고객 QBR·고객 접촉 일정과 내부 SAM 검토 일정을 별도로 표시한다. |
| 위험·지원 | 위험 내용, 영향, 대응 업무, 책임자, 지원 요청, 해소 기록 | 고객 위험·업무 지연·정보 미갱신을 서로 다른 표시로 관리한다. |

계열사별 서비스 현황은 기존 매핑을 활용해 ‘거래 중 / 제안 중 / 수요 확인 필요’로 표현한다. 실제 수요가 확인되지 않은 항목은 영업기회 금액에 포함하지 않는다. 서비스 확대 후보는 예상 수요, 관계자 접근 가능성, 다음 접촉 계획이 있는 것부터 검토한다.

관리 집중도는 매출 규모만으로 정하지 않는다. 성장 가능성·기존 관계·갱신 위험·관리 부담을 함께 검토하여 고객별 주간·격주·월간 주기를 정한다. 기존 고객 전체를 동일한 주기로 강제 변경하지 않는다.

## 5. 공통 관리 기준과 데이터 정리

- **검토 경고:** 다음 검토일을 넘겼으면 지연, 앞으로 7일 이내면 예정으로 표시한다. 다음 검토일이 없으면 일정 미설정으로 구분한다. 기존 검토 주기를 이용한 날짜 계산값은 제안값으로 제공한다.
- **최근 활동:** 파일 저장일을 고객 접촉일로 쓰지 않는다. 최근 접촉일·진행 메모 등록일·내부 검토 완료일을 구분한다.
- **위험 상태:** 승인된 고객 위험 상태를 모든 화면의 공통 기준으로 사용한다. 변경 이유·변경자·변경일을 남긴다. 오래된 메모 등록이나 기한 지연만으로 고객 위험을 자동 해소하지 않는다.
- **영업 연결:** 회사명·별칭 매칭을 활용하되 충돌 후보를 확인할 수 있게 한다. 영업건별 주관 SAM 고객과 실제 거래 계열사를 확정하고 전체 합계는 영업건 ID로 중복을 제거한다. 복수 고객과의 관련성은 조회용 관계로 유지한다.
- **Pipeline:** 활성 영업·보류·수주·실주의 포함 기준을 확정하여 대시보드·고객 상세·회의 화면에 동일하게 적용한다. 기회별 마감 예정일·담당자·원본 수정일을 전달한다.
- **금액:** 현재 연결 Pipeline UI는 KRW 표시다. USD 전략목표와 혼합 합산하지 않는다. 기회금액, 실제 연간 매출, 성장목표는 별도 지표로 정의한다. 환산이 필요한 보고에는 환율·기준일을 남긴다. PPTX의 현재 연간 매출 항목에는 기회금액을 대체 입력하지 않고, 확인된 매출 자료가 없으면 미확인으로 표시한다.
- **영문 승인:** 정식 출력 시 승인된 원본 버전과 영문 버전이 일치해야 한다. 원문을 변경하면 관련 영문을 재검토 대상으로 돌린다. 초안 출력에는 초안 표시를 넣고, 승인자·승인일·출력 기준일을 문서 버전에 연결한다.

현재 SAM은 관리자 권한으로 제한되어 있다. 담당자 직접 입력을 도입하는 단계에서는 담당 고객에 대한 입력 권한, 관리자의 전체 조회·결정 권한, 보고 승인 권한을 명시적으로 설계한다. 현재 영업 데이터가 관리자 범위로 조회되는 구조도 함께 조정해야 하며, 담당자 화면에 관리자용 데이터 전체를 전달해서는 안 된다.

## 6. 도입 순서와 완료 기준

| 순서 | 범위 | 완료 기준 |
|---|---|---|
| 준비 | 데이터 정의, 실제 운영 표본 확인 | 고객 책임자·검토 주기·영업 연결·통화 의미를 확인하고 기존 진행현황과 Action 간 중복을 정리할 기준을 확정한다. |
| 최우선 — 메일 입력 | 수신·발신 수집, Account 연결, 대화별 변경 추출, 자동 기록·예외 확인함 | 새 답장을 누락하지 않고 중복 업무를 만들지 않는다. 분류 실패와 수집 실패를 확인할 수 있다. 일반적인 고객 메일을 다시 메모로 입력하지 않아도 된다. |

| 2차 — 회의·입력 연결 | AI 후보의 과제 전환, 중복 방지, 회의 결정 기록, 검토 완료, 역할별 접근 | 승인 재시도 시 과제가 중복 생성되지 않는다. 회의 미완료 결정이 다음 회의로 이어지고, 다음 검토일을 확정할 수 있다. 담당자는 허용된 고객만 조회·수정한다. |

실제 본사 제출 일정이 임박했다면 정식 출력 승인 검사와 매출·기회금액 구분을 가장 먼저 적용한다. 초기 개선에는 이미 있는 기능을 연결하는 작업을 우선하고, 새로운 외부 CRM 도입은 전제하지 않는다.

## 7. 운영 시범안과 효과 측정

시범 고객은 검토 주기와 담당자가 다른 3~5개를 선택한다. 첫 주에는 실제 현황과 관리 시간을 측정하고 이후 4주간 개선 흐름을 적용한다. 사용자는 평소처럼 Outlook에서 업무를 진행하며 SAM의 분류 불명확·중요 변경 항목만 확인한다. 메일에 없는 통화·대면회의 내용만 보완 입력한다. 관리자는 매주 30분을 기준으로 지연·위험·결정 필요 안건을 검토하고 미완료 사항을 다음 회의로 이어간다. 시범 기간에는 메일 표본과 SAM 기록을 대조해 수집 누락·오분류·중복 비율도 측정한다.

| 지표 | 정의 | 제안 목표 |
|---|---|---|
| 후속조치 등록률 | 시범 대상 중 담당자·기한이 지정된 유효한 다음 업무를 가진 고객 비율 | 100% — 일시 중단 고객은 제외 사유 기록 |
| 검토 일정 준수율 | 기간 중 예정된 검토 중 기한 내 완료된 비율 | 90% 이상 |
| 기한 초과 업무 비율 | 미완료·미취소 업무 중 기한을 넘긴 비율 | 시작 시점 대비 감소; 기한 미설정 건수는 별도 표시 |
| 회의 준비시간 | 자료 취합부터 안건 확정까지 소요시간 | 첫 주 대비 30% 단축 |
| 정식 보고 승인 누락 | 정식 출력 결과의 미승인 필수 항목 수 | 0건 |

수주율·고객 성장률은 결과 지표로 별도 추적한다. 단기 시범에서 기능 변경만으로 매출 증가 효과를 단정하지 않는다. 알림을 추가할 경우 즉시 알림은 긴급 요청 중심으로 하고 일상 업무는 일일 요약을 기본으로 검토한다.
